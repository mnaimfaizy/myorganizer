# `@myorganizer/design-tokens`

Single source of truth for the MyOrganizer design system (colors, spacing,
typography, radius, shadow). Based on the **Secure Modernism** spec in
[DESIGN.md](DESIGN.md).

## Files

- [src/tokens.json](src/tokens.json) — **edit this.** W3C
  [Design Tokens Community Group format](https://tr.designtokens.org/format/).
- `src/generated/` — **do not edit.** Regenerated by Style Dictionary.
  - `tokens.css` — CSS custom properties (`:root { --color-primary: … }`).
  - `tokens.ts` — typed TS constants + `var(--…)` strings.
  - `roles.css` — Semantic Role variables for both colour modes, as bare HSL
    triples. Imported by the web application stylesheet; every Tailwind colour
    utility resolves through it.

## Two tiers

`tokens.json` holds two tiers, and they are not interchangeable.

- **Brand Primitives** and the **Neutral Ramp** are values. The landing page, the
  email shell, and the Mobile App theme read them directly, as TS constants or
  `--color-*` / `--neutral-*` custom properties.
- **Semantic Roles** (under `mode.light` / `mode.dark`) are slots. Each aliases a
  primitive, once per colour mode. Adding a Semantic Role is the only way to add a
  web colour utility — the Tailwind configs read roles as `hsl(var(--role))`.

The Neutral Ramp is deliberately **not** exposed as Tailwind utilities. Dark mode
cannot be expressed without an ordered greyscale, but a second elevation vocabulary
next to the roles is what [issue #632](https://github.com/mnaimfaizy/myorganizer/issues/632)
was about. See [ADR 0065](../../docs/adr/0065-tokens-json-is-the-single-source-of-web-colour.md).

Dark mode is maintained here but not shipped: nothing applies the `dark` class yet.

## Workflow

1. Edit `src/tokens.json`.
2. Regenerate: `yarn nx run design-tokens:build-tokens`.
3. Commit both `tokens.json` and `src/generated/`.

## Consuming tokens

**Tailwind classes (preferred for components):**

```tsx
<button className="bg-primary text-on-primary rounded-md shadow-card">…</button>
```

**Raw CSS:**

```css
.thing {
  background: var(--color-primary);
}
```

**TypeScript (when a value must reach JS, e.g. SVG fill):**

```ts
import { colorPrimary, colorPrimaryVar } from '@myorganizer/design-tokens';
```

## Rules

- **Never hard-code hex colors, spacing values, or font stacks in
  components.** Use a Tailwind class or import from
  `@myorganizer/design-tokens`.
- New token? Add it to `tokens.json` first, regenerate, then use it.
- Keep DESIGN.md as brand rationale (when to use a role), not a second
  palette. Update it when a semantic role or brand rule changes, not when
  a hex or spacing step moves. `tokens.json` is the machine truth. See
  ADR 0023.
