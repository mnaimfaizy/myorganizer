MyOrganizer · code review pipeline

Finding Lifecycle

An engineer opening a Pull Request in this repo, or running /code-review locally, should be able to answer from this page alone: what happens to my change, who or what can stop it, and why did this finding block when that one did not.

Grounded, mixed: source is cited by file:line; the not-yet-built pipeline is cited by ADR item number (ADR 0069, ADR 0070).

The reading test — at the validator station
“If your finding says blocking and its evidence is inferred, the validator rejects the whole report and the PR goes to a human. Find the test or the rule, or call it should-fix.”

One Pull Request, five stations, two lanes

ADR 0070, ADR 0071

The spine runs left to right through the five stations in the order they actually run. The Local lane (top) is /code-review <fixed-point> in a terminal; the CI lane (bottom) is the pull_request workflow. Both lanes converge on one object — the report JSON — through the same Reviewer and the same Validator. A box with a dot in its corner carries a note: hover it, or Tab to it. Every note is also written out under Diagram notes below, so a screenshot loses nothing.

Diagram notes

local-trigger
An engineer runs /code-review <fixed-point> in a terminal. Nothing here writes to GitHub; there is no relabel and no posted comment.
local-diff
The fixed point is pinned with git diff <fixed-point>...HEAD (three-dot, against the merge-base) — SKILL.md:25.
local-spec
Spec discovery tries, in order: the issue number in the branch name (<type>/<issue-number>-<slug> puts the issue first, AGENTS.md:133), then commit references (SKILL.md:33), then an argument, then it asks. No spec source tightens the envelope to human — only the validator's verdict math does that.
local-exit
The local run still produces the same report JSON, through the same Reviewer and Validator — but its output is written to tmp/ uncommitted (ADR 0041) and its tier is null: nothing relabels the Pull Request, because there is no Pull Request yet for a local run to relabel.
ci-trigger
The CI lane runs on pull_request: opened, synchronize, ready_for_review, reopened.
ci-concurrency
One concurrency group per Pull Request, so a superseded run is cancelled — the existing workflow already does this at ci.yml:16.
checks
The six contexts the main-branch ruleset already requires — not classic branch protection: GET /branches/main/protection returns 404, and the rules live in ruleset *main*, id 22235792, read via the GitHub API. Authoritative Lockfile Policy, Secure Install Review, Prepare Dependency Cache, Setup Affected Context, Lint, Test (ci.yml:23,142,203,335,413,459). The Test job sets DATABASE_URL (ci.yml:467) but starts no database service, so affected Jest runs without one — which is why the Reviewer's executed evidence is feasible in CI, in the same environment.
classifier
A Wired Gate, never an LLM (ADR 0070 item 2). Five inputs: affected Nx projects and their tier:* tags, the path map in tools/config/, dependency manifests, diff size, author. Output is review:auto | review:agent | review:human, written as a job output; the label on the Pull Request is only a view of it (ADR 0070 item 3). Unknown, unmatched, or error resolves to human (ADR 0070 item 5) — and a fixed “initial human set” (vault/crypto, auth/session, Prisma schema, workflows, the gate scripts, CODEOWNERS, dependency manifests) is review:human through the dependency graph even when a diff touches none of them directly (ADR 0070 item 4).
reviewer
Two sub-agents, one per axis, standards and spec (SKILL.md:15,64), each emitting a findings array; the main agent assembles the envelope and authors no finding of its own (ADR 0071 item 7). It may execute, in a git worktree under tmp/ it cannot keep (ADR 0071 item 4).
json
The Local lane and the CI lane converge here: the same Zod schema in tools/scripts/review/, the same validator, the same renderer (ADR 0071 item 8). It is one object, not two pipelines that happen to look alike.
validator
Rejects the report whole on any schema violation (ADR 0071 item 5). Derives each finding's id from axis + source + file, line and rule excluded — rule is prose the reviewer rewrites every run, not a copied citation (ADR 0071 item 6, amended by issue #718). An id only means anything within one report schema version (REPORT_SCHEMA_VERSION, currently 2): a stored artifact whose schemaVersion does not match this run's is not diffable at all — see Panel E. Computes the verdict: any blocking means request-changes; only nit means approve; otherwise comment (ADR 0071 item 5). No spec source tightens the envelope to human — see the reading test above the diagram.
decide
The reviewer produces two status checks, not one (ADR 0073 item 1): Agent Review Ran fails on a fact about the pipeline — the reviewer crashed, was cut off by the rate limit, or wrote a report the contract rejected — and Agent Verdict fails on a judgment about the diff, a request-changes verdict. Agent Verdict is advisory and appears in no ruleset; ADR 0073 rejects making it required on principle, not on a recall threshold (ADR 0073 item 2). Agent Review Ran is eligible to be required but is not required yet — that needs the GitHub ruleset, REQUIRED_CHECK_CONTEXTS, and the job-name resolution in check-review-pages.mjs (today ci.yml only) to change together (ADR 0073, Consequences). Neither check is ever a review approval (ADR 0070 item 6). review:human additionally needs a code-owner approval, which today means everything, because .github/CODEOWNERS:3 is * @mnaimfaizy. Until CODEOWNERS is narrowed, every tier meets a human in effect (ADR 0070, Consequences) — see the halt below.

The halt — station 5, GitHub decides

ADR 0070, Consequences

The spine stops here whenever the tier is review:human. Nothing on this page can advance a Pull Request past that stop without an explicit “approve as code owner” action — and, today, that stop is not conditional on the tier at all: it applies to every tier, because CODEOWNERS assigns everything to one person. That is the current state; a future, narrower CODEOWNERS is described in ADR 0070's Consequences but is not implemented and has no ADR number of its own yet. Nothing about this stop relies on motion: both states below are legible with no animation and no autoplay.

Panel A — Anatomy of a finding

ADR 0071 items 1–2, 6

Which fields the gate reads (severity, evidence.kind, whether location is present) and which it never reads (confidence, remedy, wouldBlock) — marked by more than colour: a solid accent border and the words “GATE READS” on one class, a dashed border and “DISPLAY ONLY” on the other.

axis
standards | spec — which sub-agent produced it; sorts the report into two sections that never rerank against each other.
GATE READS
severity
blocking | should-fix | nit — feeds the verdict directly.
GATE READS
evidence.kind
executed | cited | inferred, each with its own sub-fields (executed: command, exit code, output excerpt, cwd; cited: source path/rule or issue number, and the quoted rule; inferred: reasoning only). Caps what severity is reachable — see Panel B.
GATE READS
location
Optional file + line range. Its presence, not its content, decides whether a blocking finding can post as an inline comment (Panel E) or only in the summary.
GATE READS
source
The standard's path or the issue reference the finding cites — copied from the citation, not composed by the model. Feeds id below, together with axis and file.
GATE READS · IDENTITY
rule
Names the requirement the citation applies — prose the reviewer composes fresh every run. Not hashed: a single Unicode arrow degrading to ASCII once minted a brand-new finding id here, which is why it left the tuple (issue #718).
DISPLAY ONLY · NOT HASHED
id
Derived from axis + source + file, line and rule excluded — never written by the reviewer. Used to diff new / persisting / resolved findings against the previous artifact, and only comparable within one report schema version.
GATE READS · DERIVED
remedy
Free text. Shown to the human; never applied by anything.
DISPLAY ONLY
confidence
high | medium | low. Read by nothing that decides anything — feeds the trust ratchet in Panel F, not the verdict.
DISPLAY ONLY
wouldBlock
True when an inferred finding the reviewer believes would block with evidence is capped to should-fix. A calibration signal, not a gate input.
DISPLAY ONLY

The identity tuple is deliberately coarser than the finding it names: two distinct defects cited against the same source in the same file collide — and the blast radius is widest where file is empty, because an unlocated finding hashes '' for it. On the spec axis every finding cites the same issue reference as source, so every unlocated spec finding collides with every other one, not only with its file-mates. The disambiguator orders repeats by line and renumbers on the next run, so fixing one of two colliding findings moves the survivor onto the vacated id: the strip reads one persisting and one resolved, and the report re-posts the survivor under the other id — churn, a resolve plus a repost of feedback that is still on the report, not the silent loss the old four-field tuple produced. Accepted, not overlooked: that churn is the cost of a fix that stopped a false resolve from closing a thread on live blocking feedback. Issue #724 closes it with a bounded rule identifier: a closed vocabulary the reviewer selects from rather than writes.

The reading test — for finding identity
“If your change only reworks what the reviewer writes — a rule sentence, a summary — no finding changes identity. If it touches axis, source, or the file a finding is located at, every open thread for that finding is orphaned.”

Panel C — Gate Tier versus Review Tier

ADR 0012, ADR 0070 item 7

Two different label sets, on two different objects, deliberately never called tier alone.

Gate Tier

  • gate:mechanical | gate:standard | gate:full
  • Chosen before code exists
  • By to-issues or the main agent
  • An Issue Orchestration Label
  • Lives on an Issue, never a Pull Request

Review Tier

  • review:auto | review:agent | review:human
  • Computed after code exists
  • By a script (the classifier, station 2)
  • A third label set beside orchestration and surface
  • Lives on a Pull Request, never an Issue

tools/config/github-labels.json:3,80.

Why a mechanical slice can still meet a human: a Gate Tier of gate:mechanical says the work was small before it existed; a Review Tier of review:human says the diff, once it existed, touched the initial human set. Neither label can talk the other out of what it found.

Panel D — What never enters the JSON

ADR 0071 item 3, item 8

Repo standards text

Quoted.

Issue text

Quoted, capped in length, marked untrusted: true — because it is authored on GitHub, not in the repo.

PR diff & PR description

Addressed by file, line range, and head SHA — never copied. The renderer fetches the hunk from the checkout for human eyes.

And one more line: the GitHub token is never among the Reviewer's tools. A script posts the comment (ADR 0071 item 8) — the prompt-injection story in one glance.

Panel E — The report on the PR

SKILL.md:82, ADR 0071 item 7

One summary comment, edited in place per run — two sections, each sorted by severity within itself and never across (ADR 0071 item 7), nits folded, and inline comments only for blocking findings that carry a location. The strip has two forms: a new/persisting/resolved diff against the previous artifact, but only when that artifact's schemaVersion matches this run's REPORT_SCHEMA_VERSION (currently 2); otherwise the second form below, because ids minted under a different schema version are not comparable at all.

Illustrative — not a live comment

## Standards

blocking — missing await on cookies() before use (executed: failing test attached).
2 nits folded

## Spec

should-fix — issue #642 asked for a retry on lock timeout; not implemented (inferred).
new: 1 persisting: 1 resolved: 2
Illustrative — the other form, when schemaVersion does not match

No comparable previous run: the stored report is report schema 1, this run is 2.
- finding identities are only comparable within a schema version, so nothing below is marked new, persisting, or resolved.

The strip is not the only reader the version scopes: an inline thread's marker carries it too, as <!-- code-review:finding:v2:<id> --> (currently 2). A thread minted at an earlier version is neither reused nor resolved — it is left for a human, exactly like a human's own thread — because without that, the version bump would have stopped the strip's mass auto-resolve and delivered the same mass resolve through the publisher instead.

Panel F — Calibration

ADR 0071, Consequences

tools/config/review-golden-set.json holds expected findings as the same tuples, hashed the same way; recall is set intersection. Replay is a required check on Pull Requests touching the skill, schema, validator, renderer, or workflow. The set is seeded from the ADR 0053 and ADR 0065 incidents. The envelope's model and durationMs feed the trust ratchet — how a prompt change gets caught before it reaches a PR.

tools/scripts/check-review-pages.mjs diffs this page against its sources on every commit; it reads the embedded review-lifecycle-manifest block below. requiredCheckContexts are ci.yml job names, agentVerdictCheck is the job name in code-review.yml (the Agent Verdict check), agentReviewRanCheck is the sibling job name for the pipeline-fact check, gateTierLabels come from tools/config/github-labels.json, and the rest are the constants tools/scripts/review/schema.mjs exports.
