The loop, and the two ways out of it

Both pipelines have the same shape and their own shared cap of 3. The retry always goes back to the author, at the same tier.

Ordinary retry
Backwards, counter up
REJECTED at TestReviewer or FAIL(test_wrong) at TestRunner sends the item back to TestScaffold. FAIL at ComponentReviewer sends it back to ComponentBuilder. Cap 3, shared across the loop.
Escape hatch · sideways
FAIL(code_broken)
The implementation is wrong, not the test. Retrying the test author would be pointless, so this bypasses the counter entirely and exits on the first occurrence — straight to a human.
Escape hatch · terminal
ESCALATE at cap 3
Exits the loop to the orchestrator and then to a person: “recurring issues need human judgment.” It never buys more compute. No path in this system answers failure by moving up a model tier.

Every place the system stops

Eleven human gates. Three of them — the type:hitl label, E2E review and final integration — change how the system feels to work with more than the rest.

1/to-prd test-seam approval
Are these the right seams to verify the feature at?
Never acted on → the PRD is never written.
2/to-issues slice quiz
Is this breakdown right? Explicit approval is required before any issue is published.
Never acted on → no slices exist.
3type:hitl slice labelWEIGHTED

Never acted on → the dispatcher skips it forever.
4status:blockedSELF-CLEARING

Blockers never close → stays blocked.

Never acted on → the spec is written but never run.

Approve the doc changes before anything is written.
Never acted on → TECH_STACK.md drifts.
7Escalation at retry cap 3
“Recurring issues need human judgment.” The exit buys attention, not a bigger model.
Never acted on → work stalls at the orchestrator.
8FAIL(code_broken)

Never acted on → work stalls at the orchestrator.
9Final integrationWEIGHTED

Manual workflow_dispatch from release/* only; the tag follows a successful run.
Never acted on → no release.

Approve any model migration. Detection opens an issue; it never rewrites the pins itself.
Never acted on → the pins stay as they are.

Read the motion literally

Forward is progress, backward is rejection, sideways is an escape hatch, and a full stop is a person. Nothing here moves for decoration. With prefers-reduced-motion set, the same states advance as a click-through stepper with no transitions — the identical page, minus the travel.

Two boundaries worth naming

GitHub is read for issues and written only for status labels and a completion comment. Nothing is pushed to origin by any agent — in the AFK path the git panel stays at nothing has reached origin until the last human step.

What is not drawn here

No agents, verdicts or gates beyond the ones specified. Where the source is silent — the exact retry ordering when both pipelines fail in the same slice, and whether the sandbox rebases or re-cuts on a second attempt — the journey shows the given path and stops rather than inventing one.
