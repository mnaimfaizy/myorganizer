MyOrganizer · vault architecture

Only ciphertext crosses this line.

Personal data is encrypted on the user's own device under a key derived from a passphrase that never leaves it. The MyOrganizer backend and Google Drive both store nothing but ciphertext, and neither can decrypt it even in full compromise.

New here? Watch The life of a vault first — it is the same system told as a story. This page is the reference you come back to.

READ THIS FIRST · THE #1 NEWCOMER CONFUSION

Two independent locks. Signed in is not unlocked.

LOCK 1 · ACCOUNT AUTH
A JWT
Gates the vault endpoints. The server checks who is asking, and hands over the rows it holds.
LOCK 2 · VAULT UNLOCK
The passphrase
Gates the plaintext. The server has no part in it, holds no input to it, and cannot perform it.

So: “why is my vault locked when I'm already logged in?” Because the server can hand over every byte it holds and none of it is readable. Authentication decides whether you receive the ciphertext. Only the passphrase decides whether it means anything.

Every figure here is scoped to the vault. IV_LENGTH is 12 in the vault; the backend's YouTube token encryption declares a constant of the same name at 16. Same identifier, different subsystem — a value is only true inside its scope.

“Export” means two different things

Same word in the codebase, two artifacts, different trust properties.

CLIENT-SIDE EXPORT
A portable encrypted envelope
schemaVersion
exportId · UUID v4, per export
exportedAt
meta · kdf params + both wrapped MKs
blobs
The file the user downloads. Self-contained and decryptable anywhere with the passphrase.
SERVER-SIDE EXPORT
POST /vault/export
Returns the user's stored ciphertext rows — the same opaque blobs Zone B already holds.
A data-portability dump. The server decrypts nothing; it cannot.
SYNC CONFLICTS
The one place the user arbitrates
Writes carry an ETag and an If-Match. On a mismatch the user chooses:
keep-local keep-remote
There is no merge, and there cannot be one: the server cannot merge what it cannot read.

Import is a hostile-input path

An envelope is a file the user could have received from anywhere. The ordering is the point: cheap rejections first, decryption last. All nine classified error codes are shown — nothing is omitted.

0
Fetch the envelope
From disk or from Drive. If the bytes never arrive, nothing else runs.
network-failed
1
Size cap — 10 MB, scoped to envelope parsing
Enforced on the envelope text before a single byte is parsed. This is not a global vault limit: the backend's own caps are tighter and apply elsewhere.
oversize
2
Strict schema validation
Unknown blob keys, malformed shape, or zero blobs are all rejected outright.
corrupt-file unknown-blob-type empty-envelope
3
Schema version gate
An envelope newer than this client is refused by design — there are no backward migrations, ever. A non-integer schemaVersion, or one with no forward path, is unsupported.
schema-version-downgrade schema-version-unsupported
4
Replay detection
The last 10 exportIds live in IndexedDB; an in-memory ring buffer where it is unavailable.
replay-detected
5
Forward migration
Older schema versions pass through a migration registry before use. Forward only.
no error code
6
Only now is anything decrypted
Unwrap the master key from the envelope's meta, then the blobs. A structurally perfect envelope still fails here if the passphrase is wrong.
decrypt-failed

Import never touches your vault until it fully succeeds

Stage, then commit. The candidate vault is assembled entirely in memory; the existing local vault is not written to until every check has already passed.

1
Parse and validate
The gauntlet above.
2
Replay lookup
Has this exportId been seen?
3
Forward migration
Up to the current schema version.
4
Stage in memory
No writes yet. Nothing on disk has changed.
5
Atomic commit
A single storage write.
6
Record the exportId
Into the replay tracker — last of all.
If anything fails, the existing vault is untouched.
Failure at any phase leaves no partial state — there is nothing to roll back, because nothing was written.
The ordering subtlety worth drawing
The exportId is remembered after the commit, not before. A failed import therefore does not burn a legitimate envelope's one-time use.

Auto-backup
A scheduler runs backups on user-controlled preferences, applies retention limits, and cleans up pending files. It moves no new kind of data — it only repeats crossing 3 on a timer, and reports crossing 2 afterwards.
