# Review Tier replay over 200 merged Pull Requests (2026-09-06)

Research date: **2026-09-06**. Frozen at that date: the numbers below come from `yarn review:tier:replay --limit 200` run against the graph, tags, and path map as they stood on branch `feat/review-tier-classifier`, and will not be updated. Decision context: [ADR 0070](../adr/0070-a-review-tier-is-a-fact-about-the-diff-and-a-gate-tier-is-a-decision-about-the-work.md), whose Consequences section asks for exactly this replay before the classifier gates anything.

## Question

Would the Review Tier classifier (`tools/scripts/check-review-tier.mjs`, rules in `tools/config/review-tier-paths.json`) have tiered the last two hundred Pull Requests merged into `main` the way a careful reviewer would, and what do its thresholds need to be?

## Method

`gh pr list --state merged --base main --limit 200` supplies each Pull Request's file list with per-file additions and deletions, its author, and its labels. Each is classified with **today's** Nx graph, `tier:*` tags, and path map. That is the question the replay answers (would the current rules have tiered this right?), not a reconstruction of history: a project that has since moved or been deleted shows up as `unmatched`, which is `human`, and is reported rather than fixed.

Sample shape: median 5 files and 274 lines per Pull Request; 75th percentile 14 files and 858 lines; 90th percentile 34 files and 3,457 lines. All 200 were authored by the repository owner, so the author signal never fired on its own.

## First pass

Initial thresholds were a guess: `auto` at most 10 files and 200 lines, `agent` at most 80 files and 3,000 lines; blast radius `auto` at most 3 projects, `agent` at most 20.

| Tier    | Pull Requests | Share |
| ------- | ------------: | ----: |
| `auto`  |             3 |    2% |
| `agent` |            50 |   25% |
| `human` |           147 |   74% |

Five things stood out on hand-checking the `human` set.

1. **`package.json` made 55 Pull Requests human, and 41 of them never touched `yarn.lock`.** They added an npm script. CI installs with `--immutable`, so a `package.json` that pulls in a new dependency without a lockfile change cannot merge; a manifest change with no lockfile change is scripts and metadata, not a dependency change. The rule was split: `dependency-lockfiles` (`yarn.lock`, `.yarnrc.yml`, `.npmrc`, the foreign lockfiles) stays `human`; `package-manifests` is `agent`.
2. **Every Storybook story Pull Request against `web-ui` was human by reach.** `web-ui` is `tier:agent`, but `web-pages-vault` and `web-vault-ui` (both `tier:human`) import it, so the graph walk marked six story-only Pull Requests (#369 to #374) human. A story, a test, or a Markdown file cannot change what a dependent project runs. The map gained `reach.exclude`: those files still count toward their own project's tier, but never seed the dependency walk. A single runtime file alongside them seeds it again.
3. **The sandcastle directory was unmatched.** Fifteen Pull Requests touched the orchestrator under `.sandcastle/`, which dispatches agents with a token and merges slices into integration branches. It is now an explicit `human` rule (`orchestrator`) rather than an accidental one.
4. **Every sub-agent file counted as review pipeline, making 29 Pull Requests human.** Most sub-agents under `.github/agents/` do not judge code. The rule was narrowed to the code-review skill, the report contract, and the reviewer and audit agents; the rest fall to `agent-instructions` (`agent`).
5. **The 200-line `auto` ceiling caught prose.** #422 (one file, 258 lines, an upstream brief) was `agent` by size alone. The ceiling moved to 300 lines. The size signal otherwise barely matters: without it, one Pull Request changes tier.

The `unmatched` paths that remain after the tuning (17 Pull Requests) all sit under `libs/web/pages/vault-settings` and `libs/web/pages/vault-export`, two projects that no longer exist. Expected for a replay, and correct behaviour for a live Pull Request that adds a project without a `project.json`: `nx:tags:check` fails it and the classifier says `human`.

## Hand-check

**The four `auto` Pull Requests** are #611, #501, #439, and #422: one or two Markdown files under `docs/`, 75 to 258 lines, by the owner. All four are correctly `auto`.

**A sample of `agent`** reads right: glossary and ADR additions (#610, #607, #586, #523), e2e fixes confined to `myorganizer-e2e` (#629, #559), page work that reaches only agent projects (#539, #429, #211), the Storybook series (#369 to #374, #486) now `agent` after the reach exclusion, and script-only `package.json` edits.

**`human` is dominated by the tooling the repository is made of.** 62 Pull Requests touch `tools/scripts/lib`, `tools/config`, a `check-*.mjs`, or a `project.json`; 26 more touch other files in the `tools` project, which is `tier:human`; 28 touch a workflow. Together with the vault, auth, backend, and orchestrator projects this is the human set ADR 0070 item 4 names, and it is the majority of what this repository merges. Only one Pull Request is human by size alone (#238, 33 files and 6,036 lines, a form-context fix that should have been split), and only one by reach alone (#486, a `web-ui` runtime change).

**Nothing in the `human` set looked wrong**, in the sense of a Pull Request a careful reviewer would have waved through without reading. Several look heavier than they need to be, and every one of those traces to one rule: `**/project.json` under `gates-and-their-config`. A new library's `project.json` is a human path because the `tier:*` tag on it is the classifier's primary signal. That is the right default while the tag vocabulary is a week old.

## Thresholds adopted

| Threshold           | Value                    | Basis                                                                            |
| ------------------- | ------------------------ | -------------------------------------------------------------------------------- |
| `size.auto`         | 10 files, 300 lines      | Above the median Pull Request; keeps a single research brief `auto`              |
| `size.agent`        | 80 files, 3,000 lines    | Roughly the 90th percentile of lines; 24 of 134 human Pull Requests are over it  |
| `blastRadius.auto`  | 3 projects               | A page plus the app that imports it plus its e2e project                         |
| `blastRadius.agent` | 20 projects              | `web-ui` reaches 14; anything wider than 20 of 33 projects is a workspace change |
| `reach.exclude`     | stories, tests, Markdown | Cannot change what a dependent project runs                                      |

## Limits

- Historical paths are classified against today's graph. Two deleted projects account for every remaining `unmatched`.
- `gh pr list` reports additions and deletions per file; binary files count as zero lines, as they do in `git diff --numstat`.
- The replay cannot see file content, so the `package.json` split rests on the immutable-install argument, not on inspecting which keys changed. A `packageManager` bump without a lockfile change would classify as `agent`.
- Every author in the sample is the owner. The author signal is untested against a real external contribution.
